# WeLink Message Exporter

Windows desktop tool to export selected WeLink group or private conversations to UTF-8 TXT files.

## Features

- Categorize conversations into **All / Private / Group** and search locally.
- Latest-message ordering follows the order returned by WeLink for the current recent-conversation snapshot. Timestamp probes are display-only. Native pinned-first sorting is enabled only if the CLI response explicitly exposes a pin flag.
- A manual **Refresh conversations** merges newly returned group/private chats without putting them at the bottom, preserves selection, clears stale search/type filters, and returns the list to the top. The existing local conversation index is retained.
- To avoid waiting for a large batch of history requests, the app displays the server's recent-chat ordering immediately and probes the newest message timestamp of up to twelve recent conversations asynchronously (up to three concurrent read-only queries). Unconfirmed timestamps are labeled; the UI remains usable, and refresh/export cancels stale probes.
- The recent-chat API shown in the supplied CLI sample has no reliable per-chat timestamp or pinned bit; therefore previously unknown chats use a temporary recent-order fallback until timestamp lookup succeeds, and full historical conversation enumeration is not claimed.
- Discover conversations through recent chats and WeLink CLI person/group search. Manually add a `group_id` or private `target_account` for older conversations.
- Select one or multiple conversations, and set an **inclusive date range** (Beijing time, UTC+08:00).
- Fetch historical messages with message-ID pagination, de-duplicate and sort chronologically, including your own messages.
- Resolve senders' names and employee numbers when the contact API supplies them; otherwise preserve the sender account.
- Export TXT with original message line breaks; non-text messages retain their raw textual descriptors. The tool does not download attachments.
- Cancel operations, view progress/log messages, and safely discard incomplete export files.
- Fully dark date controls with a custom dark calendar popup; matching input, focus, selection and scrollbars.
- Interactive login starts the real `welink-cli auth login` command in a visible console, waits for mobile QR approval without an arbitrary timeout, verifies `auth status`, and refreshes conversations on successful login. Use **Cancel** to stop a pending login.
- Export diagnostic logs to `%LOCALAPPDATA%\WeLinkMessageExporter\logs` without message bodies or tokens.
- Handle different history response envelopes for new or older private chats. When the standard `chatInfo` field is absent, retry with an explicit older-message direction and smaller pages; only a confirmed empty page/count is treated as no history.
- Include a short response-shape summary (JSON property names and result code only) if a chat still fails. This distinguishes API format or access problems without logging private message content.
- TXT files with zero messages now explicitly state that no messages were returned for the selected date range.

## Requirements

- Windows 10/11 with .NET 8 SDK (for building).
- Node.js, WeLink PC and the authorized internal `@welink/welink-cli` installation.
- Sign in via `welink-cli auth login`. The app provides a **扫码登录** button that runs the same CLI QR flow in a separate console.
- The CLI executable and phone are not bundled with this application. The QR code is rendered by the official CLI, not generated by the exporter.
- Follow the WeLink and company data-handling rules for chat exports.

## Run and build

The development launcher uses a non-incremental build to regenerate WPF XAML bindings after UI changes, avoiding stale generated control fields.

- `run_dev.bat` — build and run.
- `build_release.bat` — publish self-contained `win-x64` app to `publish/win-x64/`.
- `diagnose.bat` — check the local .NET / WeLink CLI installation and locate startup/crash logs.

On startup the app opens its window first, then checks CLI login status and refreshes conversations. Recoverable CLI errors are displayed without closing the window. Fatal startup and dispatcher exceptions are recorded to `%LOCALAPPDATA%\WeLinkMessageExporter\logs\startup-crash.log`. If that directory is inaccessible, the fallback is `%TEMP%\WeLinkMessageExporter-startup-crash.log`. No credentials or message bodies are intentionally written to these logs.

The distributed executable still calls `welink-cli.cmd` installed on the local computer. The included `login_auth.bat` must stay beside the built/published `.exe` (the project automatically copies it). It does not bundle credentials or WeLink CLI itself.

## Completeness and safety

WeLink CLI documents **recent conversations**, keyword searches and history queries, but not a global enumeration of every past conversation. Therefore no tool can truthfully promise exhaustive conversation discovery using only these interfaces. The list combines recent results, keyword searches, manually added chats and a local conversation index that persists between runs.

During history extraction, pagination continues towards older messages until the specified start date or history exhaustion. If the cursor or response format fails, the affected chat is marked failed instead of exporting a silently truncated TXT. Chat history visibility still depends on what the authenticated WeLink account/API can retrieve.

Conversation sorting metadata, WeLink pin flags when supplied by the CLI, conversation and resolved-contact indexes are stored under `%LOCALAPPDATA%\WeLinkMessageExporter`; message bodies are written only to the selected export directory. No chat messages are sent to third-party services.

## Troubleshooting a recent private chat

If a recently contacted person fails to export, verify that the private conversation uses their **W3 account**, not their employee number. The supported history command is:

```powershell
welink-cli im query-history-message --user-account "YOUR_W3_ACCOUNT" --query-count 20
```

The application automatically tries compatible query variants when a successful API response lacks the standard message array. If all variants fail, open **Diagnostic logs** in the app and inspect the property-name-only response summary. Do not share actual chat text, bearer tokens, or QR-login credentials.

A response with no `chatInfo` and no explicit zero-count indicator cannot be safely assumed to mean "no messages". Such chats remain failed so that the tool never silently creates an incomplete export.

## Interface and scrolling

The conversation list scrolls vertically only. The scrollbar track controls thumb length; one mouse-wheel notch advances one conversation. Long conversation names are truncated visually without modifying exported data. Manual conversation entry is located in the scrollable settings panel and can be reached using the shortcut below the conversation list.

Pinned badges are based on recognized fields in the live CLI response, not a local pin setting. The list shows the counts of pinned, confirmed and unconfirmed conversations separately. The supplied reference does not establish the native pin-field schema; if the CLI response lacks a recognized flag, native pin ordering is unavailable. The program never changes WeLink pin settings.

## Extraction

Extract into the parent directory (for example, 7-Zip > Extract Here). The archive contains one top-level `WeLinkMessageExporter/` folder. Windows Explorer's Extract All may suggest a separate destination based on the ZIP filename; choose the parent directory instead.
